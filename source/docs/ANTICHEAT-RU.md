# WARDOGS Fire Control: системное взаимодействие и правила игры

Проверено 7 октября 2026 года. Этот документ описывает реализацию 2.5.1 и отдельно отмечает исторические проверки зависимостей. Сборка, работа Windows API и соблюдение правил издателя — разные виды проверки. Одобрение BULKHEAD/Team17 для этого приложения неизвестно; обещать отсутствие блокировок нельзя.

## Что делает приложение

| Механизм | Реализация исходников | Граница проверки |
|---|---|---|
| Основной режим | Alt+X всегда автоматически ищет активный черновик координат орудия независимо от сохранённой своей области; надёжная пара включает мини-карточку. Средняя кнопка читает полные осевые подписи около курсора карты. Ручной калькулятор доступен отдельно | Локальная автоматизация расчёта не подтверждает разрешение использования помощника в матче |
| Интеграция с игрой | Игровые функции, автопоиск черновика и средняя кнопка включены по умолчанию. Профиль без маркера нового сценария (`quick_workflow_version=1`) переводится на этот сценарий | Последующий выбор отдельного калькулятора сохраняется; клавиши после конфликта могут отличаться от Alt+X/Alt+C и показаны в UI |
| Горячие клавиши | `RegisterHotKey`, отдельный поток очереди `WM_HOTKEY`, только заданные сочетания | Windows резервирует эти сочетания; конфликт виден в программе. Нет наблюдения всех нажатий |
| Средняя кнопка | Включена в настройках по умолчанию; `WH_MOUSE_LL` зависит от включённой интеграции и настройки мыши. Чтение разрешается после принятия орудия, независимо от мини-карточки, `game_mode_` и возврата Alt+C. Физическое нажатие передаёт точку в ограниченную очередь | Это всё ещё глобальный мышиный hook. Непринятый новый захват орудия запрещает расчёт по старой позиции; снимок и повторы допустимы только для того же переднего окна и положения курсора |
| Снимок экрана | GDI `GetDC`/`BitBlt`, предел 16 млн пикселей. Черновик ищется в верхней левой четверти client RECT; два поля карты берутся из одного снимка рядом с курсором внутри client RECT. В полях выбирается полная строка нужной оси, фрагмент курсора на границе отделяется от текста. Своя область остаётся дополнительной настройкой | Передний HWND проверяется до/после; для карты дополнительно проверяются курсор и геометрия. Caption/class не доказывают подлинность процесса; чёрный/неполный снимок не исправляется обходом защиты |
| Карточка и прицел | Отдельные Qt-окна поверх экрана; прозрачность для кликов меняется только у собственных окон | Не внедряются в графический движок игры. Сам прицел остаётся функцией с неизвестным одобрением издателя |
| Проверка активного окна | Заголовок WARDOGS/WardogsClient и класс UnrealWindow | Это приблизительная проверка окна; она не доказывает подлинность процесса и не является границей безопасности |
| Файлы и запуск | Свой каталог приложения, собственные модели/настройки/журнал; пользовательские права `asInvoker` | Рабочее приложение не меняет установку игры и не запускает античит/игру от имени администратора |

По прямой просьбе SoNiX отдельно выполнено чтение метаданных каталогов игры, её обычной конфигурации и доступных журналов. В проверенных Logs/Telemetry файлов нет; источник выбранных X/Y не установлен. Это ограниченное инженерное исследование описано в [отдельном документе](COORDINATE-SOURCES-INVESTIGATION-RU.md). Рабочее приложение не наблюдает за игровыми журналами и не получает координаты из файлов. Чтение памяти процесса, внедрение, изменение игровых настроек, синтез игрового ввода и анализ защищённых ресурсов в этом исследовании не выполнялись.

В исследованном собственном коде приложения отсутствуют чтение/запись памяти чужого процесса, `CreateRemoteThread`, внедрение DLL, драйвер, синтез ввода (`SendInput`/`keybd_event`/`mouse_event`), изменение игровых файлов, остановка служб античита и подмена его сообщений. Также удалено открытие чужого процесса для определения foreground EXE. Это вывод по нашему коду и прямым импортам EXE; он не означает отсутствие этих API во всех DLL среды исполнения и не описывает закрытые правила обнаружения Elytra.

## Граница зависимостей Qt 6.8.3

В поставляемых `qwindows.dll` имеются импорты `SendInput` и `OpenProcess`, в `Qt6Core.dll` — `OpenProcess`. Импорт означает наличие вызываемой функции, а не её вызов при каждом запуске. Проверены конкретные первичные исходники официального тега Qt `v6.8.3`; вызовы не скрываются и не удаляются из системных библиотек.

Обычный `QWidget::activateWindow()` передаёт запрос в `QWindow::requestActivate()`. Стандартная политика Windows-плагина вызывает `SetForegroundWindow`/`SetFocus`; `raise()` меняет положение собственного окна через `SetWindowPos` с `SWP_NOACTIVATE`. В этих путях **нет синтетического Alt или `SendInput`**. Прицел и мини-карточка уже используют `WA_ShowWithoutActivating`/`WindowDoesNotAcceptFocus`; интерактивная настройка прицела допускает обычный фокус своего окна. Внутреннюю принудительную политику `AlwaysActivateWindow` приложение не включает. [Qt QWidget](https://github.com/qt/qtbase/blob/v6.8.3/src/widgets/kernel/qwidget.cpp#L12965), [Qt QWindow](https://github.com/qt/qtbase/blob/v6.8.3/src/gui/kernel/qwindow.cpp#L1284), [Qt Windows activation](https://github.com/qt/qtbase/blob/v6.8.3/src/plugins/platforms/windows/qwindowswindow.cpp#L3005), [Qt Windows raise](https://github.com/qt/qtbase/blob/v6.8.3/src/plugins/platforms/windows/qwindowswindow.cpp#L1284), [стандартная политика](https://github.com/qt/qtbase/blob/v6.8.3/src/plugins/platforms/windows/qwindowsapplication.h#L48).

`SendInput` найден в `startDoDragDrop()` Windows-плагина: Qt преобразует пользовательское перетаскивание пальцем/пером в мышиное движение и нажатие для OLE drag-and-drop. Пользовательское сенсорное перетаскивание текста в Qt-виджете потенциально может попасть в эту ветку; получатель событий и классификация античитом динамически не проверялись. Поэтому утверждение «вся среда исполнения никогда не генерирует ввод» не подтверждено. [Qt Windows drag-and-drop](https://github.com/qt/qtbase/blob/v6.8.3/src/plugins/platforms/windows/qwindowsdrag.cpp#L652), [вызов SendInput](https://github.com/qt/qtbase/blob/v6.8.3/src/plugins/platforms/windows/qwindowsdrag.cpp#L711).

`OpenProcess` в Windows clipboard-плагине проверяет отладку соседнего viewer при резервном старом механизме clipboard chain, если регистрация современного format listener не удалась. В QtCore он найден в `QLockFile` для проверки владельца/устаревшей блокировки и имени процесса; один путь запрашивает также `PROCESS_VM_READ` для получения имени модуля. Собственные настройки Fire Control сохраняются Win32 API; явных `QLockFile`, `QSettings` и `QDrag` в нашем коде нет. Это не доказывает отсутствия всех косвенных библиотечных вызовов. [Qt clipboard listener](https://github.com/qt/qtbase/blob/v6.8.3/src/plugins/platforms/windows/qwindowsclipboard.cpp#L152), [Qt clipboard OpenProcess](https://github.com/qt/qtbase/blob/v6.8.3/src/plugins/platforms/windows/qwindowsclipboard.cpp#L188), [Qt lock-file](https://github.com/qt/qtbase/blob/v6.8.3/src/corelib/io/qlockfile_win.cpp#L76).

Для обычного показа/подъёма окон менять политику фокуса не требуется: выбранный Qt-путь уже не использует `SendInput`. Хеши источников и локальных DLL, их версии и проверенные точки вызова записаны в `analysis/verification/v2.1/safety/qt-dependency-audit.json`. Метаданные DLL не удостоверяют полное соответствие бинарника проверенному тегу исходников. Полная динамическая трассировка всех DLL и сенсорных сценариев не проводилась. Эти сведения уточняют техническое поведение зависимостей; разрешение издателя и отсутствие санкций по-прежнему неизвестны.

## Что изменено в системном вводе

Клавиатурный `WH_KEYBOARD_LL` заменён на `RegisterHotKey`. Удалены `GetAsyncKeyState` и запись необработанных нажатий клавиш. Сохранились индексы действий и прежние интерфейсы парсера/обработчика; callback доставляется из собственного потока и передаётся в Qt через queued-вызов. В журнал попадают запуск/остановка и индекс явно выбранного действия.

Команды захвата и прицела исполняются только при активном собственном окне или подходящем окне WARDOGS. Команды возврата и разблокировки собственной карточки остаются доступными независимо от фокуса. Регистрация Windows всё равно резервирует включённые сочетания глобально; проверка фокуса не делает их сквозными для других программ.

Набор сочетаний регистрируется полностью либо откатывается. Для занятого другим приложением сочетания проверяется не более трёх вариантов с дополнительными Ctrl/Shift для той же клавиши; фактическая замена явно показана и сохраняется. Чужая регистрация не снимается. Исчерпание вариантов и другие ошибки Windows приводят к русской ошибке и полному откату. F12 и сочетания с Win отклоняются до регистрации; повторы на удержание отключены. Windows определяет эти ограничения и доставляет `WM_HOTKEY` в очередь потока. [Microsoft RegisterHotKey, обновлено 12 июня 2024 года](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey).

Мышиный hook всегда пропускает событие дальше, отбрасывает injected-события и реагирует только на физическое нажатие средней кнопки. Движение мыши не запускает OCR, логирование или анализ траектории. Работа передаётся из hook в очередь; пока OCR занят, остаётся только последняя цель. Разрешены два однократных повторных чтения при неизменных точке и переднем окне. Alt+C возвращает собственное основное окно без отключения готовности мыши; выбор отдельного калькулятора, отключение средней кнопки или закрытие приложения освобождают hook. Чтение цели по-прежнему требует активного окна WARDOGS и принятого орудия без нового неразрешённого захвата его позиции. Microsoft описывает выполнение `WH_MOUSE_LL` в собственном процессе, без внедрения hook в другой процесс. [Microsoft LowLevelMouseProc, обновлено 14 июля 2025 года](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc).

Потоки ввода ожидают сообщения, а не опрашивают клавиши или мышь в цикле. Остановка ограничена двумя секундами. Успешный маркер остановки пишется после фактического освобождения ресурсов и окончания потока; таймаут не выдаётся за успех.

## Отдельная проблема: происхождение карт высот

Прежние `.wdt` получены из Terrain3D неофициального общественного проекта Apollyon. Его текущий legal notice ограничивает MIT исходным кодом и исключает игровые материалы; видимый CDN-адрес не даёт разрешения скачивать/упаковывать/распространять ресурсы. Отдельная CDN policy прямо называет Terrain3D, сторонние desktop-приложения и build pipelines. [Upstream legal notice](https://github.com/apollyon-sys/wardogs-calculator/blob/main/docs/legal.md), [Upstream CDN policy](https://github.com/apollyon-sys/wardogs-calculator/blob/main/docs/cdn.md), проверены 7 октября 2026 года.

Хеши подтверждают целостность данных, но не права на их использование. Эти материалы исключены из подготовки нового распространяемого пакета; повторных загрузок не выполняем. Сохранённые исходные и диагностические материалы не удаляются этим аудитом. GUI рассчитывает плоский рельеф либо использует допустимый локальный пакет, на который у пользователя есть права. API баллистического ядра принимает поправку высоты, но отдельного ручного ввода высот для всех точек пристрелки в GUI сейчас нет. Одобрение игрового помощника и разрешение на terrain необходимо выяснять отдельно.

## Проверки и оставшаяся неопределённость

Автономные Win32-тесты проверяют реальные регистрацию/конфликт/откат/освобождение горячих клавиш, очередь событий и завершение. OCR проверяется на предоставленных обрезанных изображениях чата и осевых подписей карты; собственное нативное окно проверяет цепочку Windows-захвата. Тестовое окно на отдельном desktop позиционирует курсор только у себя и восстанавливает исходную позицию; игрового ввода оно не генерирует. Результаты сохраняются по версиям в `analysis/verification`. Эти проверки не являются испытанием в живом WARDOGS и не подтверждают допуск приложения античитом, будущую классификацию помощника или отсутствие санкций в онлайн-матче.

Снижение числа hooks и системных действий не является обходом античита. Защиту игры, службы, драйверы и правила не отключаем. Запросов разработчикам или владельцам данных не отправляли. Локальный черновик отдельного запроса находится в `SUPPORT-APPROVAL-DRAFT-RU.md`.
