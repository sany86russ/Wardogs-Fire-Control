# WARDOGS Fire Control 2.5.1 — архитектура

SPH-2 starts with a direct solution and no required calibration shots. Optional Alt+I captures the displayed target/arc/bearing/MIL and the observed impact without replacing the target. The local-only correction preserves the baseline rotation, isolates firing arcs and nearby targets, and publishes accepted observations transactionally. Input/calibration epochs reject stale captures. Actual shot detection and in-game sight verification are not implemented: record each landing before changing target or arc.

Подробные модули, потоки, команды и границы проверки описаны в [русском обзоре](ARCHITECTURE-RU.md). [Расчёты](CALCULATIONS-RU.md), [правила игры](ANTICHEAT-RU.md) и [источники координат](COORDINATE-WORKFLOW-RESEARCH-RU.md) рассматриваются отдельно.

## Потоки данных

Стандартный путь орудия: **M → ПКМ → Mark Coordinates → Alt+X**. В верхней левой четверти client RECT сначала ищется белая плашка канала с тёмными буквами, затем соседняя строка координат; фоновая сцена не заполняет список строк. Для автоматического применения требуются полный единственный результат, согласие проходов, проверка уверенности/числа символов и источник активного черновика. Старое сообщение истории не подменяет неполный или пустой черновик. Успех включает игровой режим и мини-карточку; слабый/обрезанный результат требует проверки.

Физическое нажатие средней кнопки передаёт точку в Qt-очередь вне `WH_MOUSE_LL`. Два поля около курсора захватываются одним GDI-снимком, затем читаются как X и Y. Прямоугольники ограничены клиентом; перед/после проверяются переднее окно, курсор и геометрия. Старый чат в этом пути не используется. Пока OCR занят, остаётся одна последняя цель; допустимы два повтора при том же контексте. Эпоха ввода отбрасывает устаревший ответ. На время нового чтения или ошибки прежняя наводка скрывается. Длинные граничные линии сетки исключаются из текста и признака обрезки; настоящий обрезанный знак остаётся причиной проверки. Журнал фиксирует признаки чтения без снимков и текста чата.

Qt UI работает в основном потоке. OCR запускается через `std::jthread` и возвращается queued-вызовом с `QPointer`. Основной движок — PP-OCRv6_rec_small и ONNX Runtime CPU; детектор компонентов, подготовка строки и CTC реализованы в проекте. Автоматический чат и поля карты используют основной движок независимо от сохранённого выбора для своей области. Windows.Media.Ocr остаётся дополнительным движком для ручного пути и требует установленного языка. Модель работает локально и не загружается на каждый захват.

В поле Y тонкий высокий фрагмент крестика исключается только в ожидаемой полосе курсора. Высокая граничная скобка пинга отделяется от нормальных знаков по геометрии и независимым опорным буквам. Если стрелка игрока сверху соединяет несколько знаков, минимум три неперекрытых знака должны подтвердить общую полосу шрифта; физические группы считаются по её нижней части. Проверка не выводит число знаков из ответа OCR. Полностью закрытая цифра, срезанная подпись или дробная часть и конфликт чтений не становятся автоматическим результатом.

Ширина плашки канала определяется по текущему кадру и может меняться после Tab. Короткий канал «ВСЕ» не обязан соответствовать геометрии широкого фонового блока. Для подтверждения активного поля нужны внутренние тёмные буквы плашки; строка связывается только с такой плашкой. Общий поиск сохраняет чтение прежних форматов, но не присваивает им признак активного черновика. Проверка подписи ограничена 256 кандидатами и 8 найденными плашками, с отменой и ограничениями компонентов.

## Модульные границы

| Модуль | Ответственность |
|---|---|
| `app.cpp` / `main_window.cpp` | Инициализация, единственный экземпляр, оконные переходы, контекст и отмена OCR |
| `capture` / `selection_overlay` | Физические координаты клиента/монитора, GDI, границы и ручное выделение |
| `ocr` / `windows_ocr` | Распознавание, источник пары, число символов, согласие и ограниченная жизнь engine |
| `hotkeys` / `mouse_trigger` | RegisterHotKey и событие физической средней кнопки; нет OCR в hook |
| `calculator` / `vehicle_ballistics` | Чистые расчёты L81/SPH-2, таблицы, физические направления и высота |
| `continuous_calibration` | Наблюдения попаданий, качество и поправки |
| `terrain_package` | Проверка/декодирование пакета, двулинейная высота, ограниченный LRU |
| `settings` / `logger` | Миграция INI, атомарная запись, ограниченный журнал и сигнал сбоя |
| Оконные виджеты | Представление результата, мини-карточка, прицел и настройки |

MIL табличного прицела и физический угол бросания — разные величины. L81 использует игровую таблицу и плоское расстояние/азимут; SPH-2 использует таблицы обеих траекторий и относительную высоту. В обычном сценарии поправка оценивает локальный остаток азимута/MIL без общего поворота платформы и без обязательной пары попаданий. Историческая двухточечная функция остаётся в математическом API, а не в UI. [Пределы формул](CALCULATIONS-RU.md).

Пакет рельефа содержит сетку 2 м с квантованием высоты 0.1 м и сжатые блоки. Открывается выбранная карта, декодируются только нужные блоки. Хеши удостоверяют целостность, а не права. Community `.wdt` исключены из нового комплекта; допустимый локальный пакет подключается отдельно. Лицензии и `TERRAIN_DATA_NOTICE.md` сохранены.

## Windows и настройки

Клавиатурные сочетания регистрируются через `RegisterHotKey` с `MOD_NOREPEAT`, без глобального клавиатурного hook. При занятой клавише разрешены до трёх дополнительных Ctrl/Shift-вариантов; другие ошибки откатывают весь набор. Фактические назначения показаны и сохранены. Мышиный hook всегда передаёт событие дальше и существует только в игровом режиме. Рабочее приложение не читает память/файлы игры и не управляет наведением/огнём. Зависимости Qt и ограничения этих выводов рассмотрены в [античит-документе](ANTICHEAT-RU.md).

Игровые функции, автопоиск черновика и средняя кнопка включены по умолчанию. Профили без маркера нового сценария мигрируют к `quick_workflow_version=1` и клавишам орудия Alt+X / возврата Alt+C с учётом конфликтов. После сохранения явный выбор отдельного калькулятора сохраняется. Новый профиль находится в `%LOCALAPPDATA%\WardogsFireControl\settings.ini`; прежний импортируется без записи в него. ANSI импорт сохраняется через временную UTF-16LE копию и атомарную замену, предел 8 МиБ; сторонние ключи/комментарии сохраняются.

Ручная область хранит имя монитора, относительные физические координаты и эталонные размеры. Каждый захват проверяет диапазон, чтобы изменение разрешения/отключение монитора не стало молчаливой заменой области. Нативное выделение начинается на одном мониторе и ограничивается им. Автоматические поля карты ограничены client RECT.

Мини-карточка и прицел — собственные Qt-окна поверх других окон. Прицел масштабируется по высоте относительно 4:3 и не растягивается по ширине сверхширокого экрана. Обычный порядок окон подходит для оконного режима без рамки; exclusive fullscreen может скрывать наложение или давать неполный снимок. Приложение не добавляет DirectX Present Hook/инъекцию для обхода этого ограничения.

## Доказательства и пределы

Проверки используют чистые математические тесты, предоставленные обрезанные изображения чата и собственное нативное окно на отдельном desktop. Последнее проверяет настоящий путь Windows GDI/foreground и два поля рядом с курсором; тестовый инструмент сохраняет и восстанавливает курсор. Это не live WARDOGS. Квитанции сохраняются по версиям в `analysis/verification`; длительные утечки, все масштабы HUD, точность попаданий и одобрение античитом ими не подтверждаются.

Полные исходники опубликованной основы сохранены; исходный EXE модификации не изменён. Неизвестные внутренние детали и побитовое тождество не обещаются. Одобрение BULKHEAD не получено; скрытность и отсутствие санкций не гарантируются.
